文章标题：M14 系统通知预留与轻量实现技术方案

# 一、背景

M14 对应项目规划中的“系统通知预留或轻量实现”。白皮书明确：通知中心只用于系统通知，不用于私信、小群或聊天。通知可以覆盖审核结果、评论回复、活动状态变化、公告发布等系统事件，但必须避免形成点对点私密沟通能力。

本阶段采用轻量实现：建立统一通知模型、通知创建服务、通知列表/已读 API，并接入部分已稳定事件。

# 二、需求范围

## 本阶段实现

| 能力 | 说明 |
| --- | --- |
| 通知模型 | 接收人、类型、标题、内容、关联对象、已读状态 |
| 通知 API | 列表、未读数量、单条已读、全部已读 |
| 通知中心页面 | 前端展示通知列表，支持标记已读 |
| 审核结果通知 | 管理员审核通过、拒绝、需补充资料时通知用户 |
| 公告通知 | 重要公告发布时通知已审核同学 |
| 评论回复通知 | 有人回复自己的评论时通知原评论作者 |
| 活动状态通知 | 管理端变更活动状态时通知发起人 |

## 本阶段不做

| 不做项 | 原因 |
| --- | --- |
| 用户之间发送通知 | 避免演变成私信 |
| 通知回复、会话、群组 | 与“不做私信和小群”原则冲突 |
| WebSocket / 实时推送 | 第一版轻量实现，轮询或页面刷新即可 |
| 邮件/短信/微信推送 | 需要额外外部服务和隐私合规，后续再评估 |
| 复杂通知偏好设置 | 第一版只保留统一系统通知 |

# 三、数据模型

## Notification

| 字段 | 说明 |
| --- | --- |
| `recipient` | 接收人 |
| `notification_type` | 通知类型 |
| `title` | 通知标题 |
| `content` | 通知正文 |
| `target_content_type` / `target_object_id` | 可选关联对象 |
| `is_read` | 是否已读 |
| `read_at` | 已读时间 |
| `created_at` | 创建时间 |

## 通知类型

- `review_result`：审核结果
- `announcement`：公告发布
- `comment_reply`：评论回复
- `activity_status`：活动状态变化
- `system`：通用系统通知

# 四、后端 API

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/notifications/` | 已审核用户 | 通知列表 |
| GET | `/api/v1/notifications/unread-count/` | 已审核用户 | 未读数量 |
| POST | `/api/v1/notifications/{id}/read/` | 已审核用户 | 标记单条已读 |
| POST | `/api/v1/notifications/read-all/` | 已审核用户 | 全部标记已读 |

# 五、事件接入方案

| 事件 | 接入点 | 接收人 | 说明 |
| --- | --- | --- | --- |
| 用户审核结果 | `accounts/admin_views.py` | 被审核用户 | 审核通过/拒绝/需补充资料 |
| 重要公告发布 | `announcements/views.py` | 已审核且未封禁用户 | 仅 `require_read_confirm=True` 的公告通知 |
| 评论回复 | `posts/views.py` 回复接口 | 被回复评论作者 | 自己回复自己不通知 |
| 活动状态变化 | `activities/admin_views.py` | 活动发起人 | 仅管理端变更活动状态通知 |

# 六、前端方案

新增页面：

```text
/notifications
```

页面能力：

- 展示通知列表
- 显示未读状态
- 点击“标记已读”
- “全部已读”按钮

导航栏增加“通知”入口，展示逻辑不做实时未读角标，避免额外轮询复杂度。

# 七、边界与风险

| 场景 | 处理 |
| --- | --- |
| 通知对象被删除 | 通知仍展示文本，不强依赖对象可访问 |
| 公告通知数量较多 | 第一版逐条创建，班级规模较小可接受 |
| 重复通知 | 事件触发时创建，不做去重；后续可按业务加唯一约束 |
| 受限/封禁用户 | 通知列表仍要求已审核且非封禁；封禁用户不可访问内部通知 |
| 私信风险 | 不提供发送接口给普通用户，不提供回复功能 |

# 八、验收标准

- 审核结果会生成通知
- 重要公告发布会通知已审核用户
- 评论回复会通知原评论作者，自己回复自己不通知
- 活动状态变更会通知活动发起人
- 用户可以查看自己的通知列表
- 用户只能操作自己的通知
- 支持单条已读和全部已读
- 不存在普通用户向其他用户发送通知的 API
- 后端检查、迁移检查、测试、OpenAPI、前端类型检查和构建通过
