文章标题：M10 生日祝福板块技术方案

# 一、背景

M10 实现生日祝福板块，用于在不暴露具体生日信息的前提下，给本月生日同学提供轻量祝福入口。

根据白皮书，生日功能必须遵循自愿公开和最小展示原则：平台不展示出生年份，不展示具体日期，只展示生日月份；用户可以选择是否填写生日月份，也可以随时关闭生日展示。生日祝福不得变成骚扰工具，系统不提供私信祝福，也不支持小群祝福。祝福内容发布在生日祝福板块内，并接受站内规则约束和管理员管理。

M10 依赖 M04 的 `Profile.birthday_month`、M05 的内容状态和展示身份能力，以及 M03 的权限基础。

# 二、需求描述

## 需求来源

| 来源 | 需求内容 |
| --- | --- |
| 白皮书 | 本月生日同学列表、生日月份展示、不展示年份和具体日期、生日祝福留言、用户可关闭生日展示、管理员可隐藏不合适祝福 |
| 模块规划 | 本月生日同学 API、生日祝福、祝福内容管理、前端生日页面 |
| 用户确认 | 新增生日展示开关；祝福发给具体用户；展示身份沿用真实姓名/昵称；后端实现隐藏/删除能力；编辑资料页增加开关 |

## 本阶段范围

M10 实现：

- `Profile.show_birthday` 生日展示开关，默认关闭
- 本月生日同学 API
- 生日祝福模型 `BirthdayWish`
- 祝福列表、发布、删除、隐藏 API
- 前端生日祝福页 `/birthdays`
- 编辑资料页增加“展示生日月份”开关

M10 不实现：

- 出生年份、具体日期或完整生日字段
- 私信祝福、小群祝福、定向私密祝福
- 生日自动提醒通知（留到通知模块）
- 独立管理后台页面（后续管理后台整合）

# 三、技术方案

## 资料模型扩展

在 `profiles.Profile` 中新增：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `show_birthday` | BooleanField | False | 是否在生日板块展示生日月份 |

只有满足以下条件的用户才会出现在本月生日同学列表：

- 用户审核状态为 `approved`
- 用户账号状态为 `normal`
- `profile.birthday_month == 当前月份`
- `profile.show_birthday == True`

## 生日祝福模型

新增 `birthdays.BirthdayWish`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `recipient` | FK User | 被祝福人 |
| `author` | FK User | 祝福发布者 |
| `content` | TextField | 祝福内容 |
| `display_mode` | CharField | 作者展示身份：真实姓名 / 昵称 |
| `status` | CharField | 内容状态：published / hidden / deleted |
| `created_at` | DateTime | 创建时间 |
| `updated_at` | DateTime | 更新时间 |
| `deleted_at` / `deleted_by` / `delete_reason` | SoftDeletableModel | 软删除字段 |

祝福发给具体用户，但展示在生日祝福板块中，不提供私信、私密留言或小群祝福能力。

## API 设计

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/birthdays/current-month/` | IsApprovedClassmate | 本月生日同学列表 |
| `GET` | `/api/v1/birthdays/wishes/` | IsApprovedClassmate | 祝福留言列表，可按 recipient 筛选 |
| `POST` | `/api/v1/birthdays/wishes/` | IsApprovedClassmate | 发布生日祝福 |
| `DELETE` | `/api/v1/birthdays/wishes/{id}/` | 作者或管理会员以上 | 软删除生日祝福 |
| `POST` | `/api/v1/birthdays/wishes/{id}/hide/` | 管理会员以上 | 隐藏生日祝福 |

## 前端页面

新增 `/birthdays`：

- 展示本月生日同学
- 选择某位同学发布祝福
- 展示祝福留言列表
- 发布时选择真实姓名或昵称展示
- 不展示出生年份和具体日期

编辑资料页增加：

- 生日月份选择（已有）
- 是否在生日板块展示生日月份（新增）

# 四、异常和边界场景

| 场景 | 处理 |
| --- | --- |
| 用户未开启生日展示 | 不出现在本月生日列表 |
| 用户未填写生日月份 | 不出现在本月生日列表 |
| 请求给未开启生日展示的用户发祝福 | 400，提示对方未开启生日祝福 |
| 请求给非本月生日用户发祝福 | 400，提示只能给本月生日同学送祝福 |
| 祝福内容为空 | 400 |
| 普通用户删除他人祝福 | 403 |
| 管理员隐藏祝福 | 状态变更为 hidden，不在普通列表展示 |

# 五、风险与取舍

| 风险 / 取舍 | 影响 | 解决措施 | 验证方式 |
| --- | --- | --- | --- |
| 默认关闭生日展示 | 初期生日列表可能为空 | 符合隐私优先原则，用户可主动开启 | API 测试验证未开启不展示 |
| 不做匿名展示 | 与白皮书“匿名展示”有差异 | 沿用用户已确认的真实姓名/昵称二选一口径，后台保留真实作者 | 序列化结果只返回 display_name |
| 不做通知提醒 | 用户可能不知道有人祝福 | 通知模块后续统一处理，避免把通知做成私信 | 当前页面内可查看祝福列表 |

# 六、验收标准

- 用户可以在编辑资料页设置生日月份和展示开关
- 本月生日 API 只返回开启展示且生日月份为当前月份的审核通过用户
- API 不返回出生年份、具体日期或完整生日字段
- 已审核用户可以给本月生日同学发布祝福
- 祝福发布时可以选择真实姓名或昵称展示
- 作者可以删除自己的祝福
- 管理会员和超级管理员可以隐藏/删除不合适祝福
- `python manage.py check`、`makemigrations --check --dry-run`、`python manage.py test`、OpenAPI、前端 typecheck 和 build 全部通过
